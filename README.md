# Coach & Horses Kitchen Pro — Render + Neon build

This package is the shared multi-user version for deployment from GitHub to Render, with live records stored in a Neon PostgreSQL database.

## What this fixes

- No Render persistent disk is required.
- The Render service can use the free web-service plan.
- Keith, Ian, Harry and the manager can sign in from separate phones.
- The OpenAI key stays on the server.
- PostgreSQL transactions and revision checks prevent one phone from silently overwriting a newer save from another phone.

## Required environment variables

- `DATABASE_URL`: the full Neon PostgreSQL connection string.
- `SESSION_SECRET`: generated by Render from `render.yaml`.
- `OPENAI_API_KEY`: optional; required for AI functions.

Do not put any of these values into GitHub.

## Deploy

1. Create a private GitHub repository.
2. Upload the files in this folder to the repository root.
3. Create a Neon project and copy its PostgreSQL connection string.
4. In Render, choose **New → Blueprint** and select the GitHub repository.
5. Enter `DATABASE_URL` and, optionally, `OPENAI_API_KEY` when prompted.
6. Deploy.
7. Open the Render web address and sign in.

The database tables are created automatically on first startup.

## Concurrent editing

This build uses optimistic revision checks. If another user saves first, the app refuses the stale save and reloads the latest shared records rather than silently replacing them. The user should repeat the last action after the refresh.

## Backups

Use the app's full JSON export regularly. GitHub stores the code, while Neon stores the live operational data.
